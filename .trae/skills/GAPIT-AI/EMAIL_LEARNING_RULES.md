# 邮件学习沉淀规则

本文件整理自 `data/gapit-resources/email-archives/` 中的真实支持邮件，用于将“高频、稳定、可复用”的经验沉淀回 `gapit-expert` skill。

## 当前可稳定吸收的规则

### 1. 数值型基因型优先走 `GD`/`GM`
- 如果用户提供的是数值型基因型矩阵，不要继续按 HapMap 路径式 `G=` 写代码。
- 优先建议：
  - `GD=`：数值型 genotype
  - `GM=`：对应 marker map
- 技能在生成代码前，应先判断用户输入到底是 HapMap 还是 numeric matrix。

### 2. HapMap 读入时必须核对 `header`
- 用户若手动用 `read.table()` / `read.delim()` 读 HapMap，再传入 GAPIT，必须提醒检查 `header` 设置。
- `header` 错误会导致 `myG` 列错位，后面常表现为结构性报错，而不是简单的文件不存在。

### 3. 安装或结果异常时，优先重新 `source()` 最新函数
- 当用户说“装不上、运行逻辑奇怪、结果明显不合理、旧脚本和教程对不上”时，优先建议重新加载最新 `gapit_functions.txt`。
- 不要默认继续在过时本地脚本上反复排错。

### 4. FarmCPU 对重复/无变异 SNP 较敏感
- 如果 FarmCPU 在 marker effect、对象重复、overmean 之类步骤报错，要优先检查：
  - 重复 SNP
  - 无变异 SNP
  - 极低多态位点
- 先做去重、过滤，再继续排查模型参数。

### 5. 个体数不一致先查 ID 对齐
- 如果报错指向 map、genotype、phenotype 个体数不一致，优先检查三者的样本 ID 与数量是否一致。
- 这类问题不要先归因于 BLINK/FarmCPU/MLM 参数。

### 6. 卡在基因型可视化步骤时，可先关闭 `Geno.View.output`
- 如果分析长时间卡住在基因型预处理或可视化相关步骤，可建议先设置：
  - `Geno.View.output=FALSE`
- 这能帮助区分：是图形输出卡住，还是数据本身/前置计算卡住。

### 7. LD decay 异常不能只怪数据
- 如果 LD decay 图明显不合理，不能只说“数据质量差”。
- 还应检查用户是否使用了旧版 GAPIT 函数；新版函数可能已经修复该问题。

### 8. PVE 很低或为 `NA` 不一定是跑错
- 解释 PVE 时要说明：
  - PVE 是相对解释率，标记越多越容易被稀释
  - 复杂性状本来就可能让单个位点 PVE 偏低
  - 多位点模型下某些传统 `R² with/without SNP` 指标可能显示 `NA`
- 不要把低 PVE 直接等同于“分析失败”。

### 9. BLINK/FarmCPU 不能按单标记效应量去理解
- 多位点迭代模型（如 BLINK、FarmCPU）不一定输出传统意义上的单标记效应量。
- 若用户关注“效应大小”，可引导其改看：
  - PVE
  - 显著位点集合
  - 整体模型解释框架

### 10. 分染色体与全基因组多位点结果不完全一致是可能的
- 对于 BLINK/FarmCPU/SUPER 这类迭代模型，不同输入范围会影响每轮放入固定效应的显著位点集合。
- 因此“单染色体结果”和“全基因组一起跑的结果”不同并不一定是错误。
- 若目标是正式结果，优先建议使用全基因组基因型整体分析。

## 如何用于 skill

- 写入 `SKILL.md` 的内容必须是“规则”和“处置顺序”，不能是邮件原文。
- 真实邮件原文与线程记录保留在 `data/gapit-resources/email-archives/`，用于追溯和后续再训练。
- 后续若新增邮件规则，应优先判断它是否：
  1. 多次出现
  2. 能转成稳定诊断顺序
  3. 不依赖某个临时版本或私下语境
