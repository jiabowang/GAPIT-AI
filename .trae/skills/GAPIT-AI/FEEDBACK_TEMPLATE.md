### 智能体代码修改处理指南

#### 1. 修改请求识别和提示
- **明确提示机制**：当用户提出可能涉及修改GAPIT代码的需求时，智能体必须明确提示：
  ```
  [智能体提示] 您的需求可能需要修改原始GAPIT代码。是否确认进行代码修改？
  - 确认：智能体将创建原始代码备份，然后实施修改
  - 拒绝：智能体将提供替代方案或解释限制
  ```
- **风险告知**：在用户确认前，必须告知修改可能带来的风险
- **备份说明**：明确说明会创建原始代码备份文件

#### 2. 修改请求识别标准
- **明确请求修改**：用户直接要求修改GAPIT函数代码
- **功能扩展需求**：用户需要现有功能之外的新功能
- **性能优化需求**：用户希望提高计算效率或减少内存使用
- **错误修复需求**：用户发现代码中的错误需要修复

#### 2. 风险提示内容
- **兼容性风险**：修改可能影响与其他软件的兼容性
- **稳定性风险**：修改可能引入新的错误或不稳定因素
- **维护风险**：修改可能增加代码维护的复杂性
- **升级风险**：修改可能影响未来版本的升级

#### 3. 用户确认要求
- **明确同意**：用户必须明确同意修改原始代码
- **风险认知**：用户必须确认已了解修改可能带来的风险
- **备份确认**：用户必须确认已创建原始代码备份
- **责任承担**：用户必须确认愿意承担修改带来的后果

#### 4. 代码修改甄别机制
- **智能体甄别**：修改完成后，智能体必须对修改的代码进行甄别：
  1. **技术评估**：检查修改的技术合理性
  2. **兼容性检查**：评估与现有功能的兼容性
  3. **性能分析**：分析修改对性能的影响
  4. **改进方案**：提出可能的优化或改进方案
- **甄别报告格式**：
  ```
  [代码修改甄别报告]
  1. 修改内容摘要：[简要描述修改内容]
  2. 技术合理性：[评估技术实现是否合理]
  3. 兼容性影响：[分析对现有功能的影响]
  4. 性能影响：[评估计算效率变化]
  5. 改进建议：[提出进一步优化方案]
  6. 社区价值：[评估对GAPIT用户群体的价值]
  ```

#### 5. 上报创造者标准
- **重大修改**：影响核心功能或性能的修改
- **兼容性影响**：可能影响与其他软件兼容性的修改
- **稳定性风险**：可能引入不稳定因素的修改
- **社区需求**：多个用户有相同需求的修改
- **发展方向相关**：与GAPIT未来发展相关的修改

#### 6. 代码更新决策机制
- **与创造者沟通**：智能体必须将甄别报告上报给创造者（您）
- **需求确认**：创造者确认是否为大多数用户的需求
- **发展方向评估**：评估修改是否符合GAPIT发展方向
- **更新决策**：
  - **更新整体代码**：如果符合大多数用户需求且符合发展方向
  - **隐藏修改**：如果不是绝大多数人需求或不符合发展方向
  - **保留用户特定版本**：为用户保留修改，但不整合到主版本

### 代码修改决策树

```
开始
├── 用户请求修改GAPIT代码？
│   ├── 是 → 继续
│   └── 否 → 结束
├── 智能体明确提示：是否改变原始GAPIT代码？
│   ├── 用户确认修改 → 继续
│   └── 用户拒绝 → 结束
├── 评估修改合理性和必要性
│   ├── 合理必要 → 继续
│   └── 不合理 → 拒绝并解释原因
├── 创建原始GAPIT代码备份
├── 实施代码修改
├── 验证修改效果
├── 在反馈信息模板中记录修改详情
├── 智能体甄别修改代码，提出改进方案
├── 上报创造者（您）沟通确认
│   ├── 大多数人都需求且符合GAPIT发展方向 → 更新整体GAPIT代码
│   └── 不是绝大多数人需求或不符合发展方向 → 隐藏修改
└── 返回给用户修改处理结果
```
